# Project Neptune — California beach board

Water-quality estimates for California beaches: enterococcus against the 104 MPN/100 mL limit, a same-day nowcast, and an experimental look at the next three days.

## Run it

```bash
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). That is the public “Beaches near me” screen: browser location, or a search by name, with no account. Each beach has a page at `/beach/<slug>`. When the roster publishes `station_key` (`agency\|station_code`), the slug is the beach name plus that key with the pipe written as `~`, for example `huntington-state-beach--orange-county~0`. Otherwise the slug is the station code plus agency, or the beach name, county, and station code. A station code alone is not the address, because the same code is used by more than one agency. The full coast board stays at `/california`.

`npm run build` compiles the production app. `node scripts/check-neptune-contract.ts` (Node 22, with type stripping) checks the parsers.

No deployment, and no production database. Auth, billing, and email alerts stay off unless you add your own local keys. The board still renders without them. PostHog is skipped when `NEXT_PUBLIC_POSTHOG_KEY` and `NEXT_PUBLIC_POSTHOG_HOST` are unset. Maps use OpenStreetMap tiles unless `NEXT_PUBLIC_CARTO_API_KEY` is set.

## Where the data comes from

All file reads go through `lib/neptuneAdapter.ts`. Column names are parsed in `lib/neptuneContract.ts`. The full shape is in [DATA_CONTRACT.md](DATA_CONTRACT.md).

1. If `NEPTUNE_V2_DIR` is set, that directory is treated as a `project-neptune-v2` checkout (`data/roster.json`, `outputs/forecast_archive/forecasts.csv`, `outputs/daily/current.csv`, `config/staleness_thresholds.json`, and the wide CSVs). The network fetch is skipped. `NEPTUNE_V2_REMOTE=off` skips it too.
2. Otherwise the app fetches `outputs/daily/current.csv` and `data/roster.json` from `eymoney13/project-neptune-v2` `main`, plus the run manifest, index bands, and staleness config when those files exist. Raw GitHub is tried first, then the contents API. A token in `NEPTUNE_V2_GITHUB_TOKEN`, `GITHUB_TOKEN`, or `GH_TOKEN` is sent when one is set. The download stays in a temp directory and is not committed.
3. If that fetch fails, the app uses the committed snapshot in `data/neptune-v2/`.
4. A wide CSV that is not in the v2 tree falls back to `public/data/southbay/`, unless `outputs/daily/current.csv` is the daily file. That file already carries the nowcast and days 1–3, so the older South Bay CSVs are not mixed in.

`data/neptune-v2/` is the committed snapshot of the 2026-10-10T14:56:12Z publish, patched because `project-neptune-v2` commit `d1fd10f` was not readable from this environment. The roster has 680 stations (177 well tested, 503 limited data), including Rincon Beach (`VCEHD|1100`) and Long Beach `CLBHHS|B-69`. The app still tries to fetch a newer copy at runtime and uses this snapshot when the fetch fails.

`/california` uses the roster file instead of the hardcoded station list. Stations with no model row show as “No estimate today.” Blank fields stay blank.

## What the board shows

- Under the limit, Near the limit, and Elevated risk, from the same cutoffs as the legend. The words live in `lib/readerLabels.ts`. A model Unsafe call is Elevated risk: a precaution, because the cutoff is set to catch about half of exceedances, so most flagged days do not exceed. On a `limited_data` beach that call is greyed, in the same dashed italic style as a low-confidence reading, with a note that the testing history is limited. A `model_pool` call stays full strength. `TIER_ELEVATED_STYLE` in `lib/tierCallStyle.ts` is the switch, and the confidence field does not override it. Over the limit is reserved for a lab result above 104 MPN/100 mL. Closed and Warning are reserved for official postings. A Neptune Index (0–100, lower is cleaner) replaces that reading on the map, the list, and the beach page. The number is the published `neptune_index` for every beach, including limited data, when that column is already on the scale in `config/neptune_index_bands.json` (the file matches `round(calibrated probability × 100)`, or that row does). A limited-data beach says “Forecast pending” with no number only when the cell is missing or still on the older higher-is-cleaner scale. Only a well-tested beach is computed from probability in that case. Day-ahead words come from `dayN_neptune_index` and `dayN_neptune_band`, not from `dayN_call` or `alert_flag`. Good is 0–24 (Safe to swim), Moderate is 25–49 (Use caution), Likely Unsafe is 50–74 and Very Likely Unsafe is 75–100 (Not safe). Those words come from the band, not from the old Safe/Unsafe call (`alert_flag`), which is not shown. A warning or closure forces Very Likely Unsafe and keeps the calculated number. Every beach with a trusted index uses that one scale. Limited data is a label, not a different cutoff. The scale is at `/california/neptune-index`. Official warnings, closures, and a lab result over 104 still come first.
- Day 1–3 forecasts in an Experimental panel (`FORECAST_HORIZON_MODE` and `FORECAST_HIDDEN_STATIONS` in `lib/forecastDisplay.ts`). A day drops that label only when `dayN_release` on `outputs/daily/current.csv` or `outputs/daily_status.csv` is `go_live`. A filled cell on the current file wins. A confidence column and `forecast_3day.csv` are not that mark. Every other look-ahead day stays Experimental. The station list is not hardcoded. `outputs/daily/current.csv` remains the daily file until that new status file is the one published.
- A published call or `final_status` of `Unknown` means the rules path did not have enough recent data. The page says “Not enough recent data to call.” It is not shown as Safe or under the limit, including when `current.csv` leaves the probability blank. A filled `call` or `probability` on that file is the current reading. `posting_status: unknown` is a different sentence, about the county feed.
- Counties named in `outputs/run_manifest.json` as stale appear on the public home, the beach page, and the California board. The board also shows a caution when `checks_passed` is false.
- Search, plus county, region, status, and roster filters. Region appears when the regions file names any.
- A clustered map, and a beach page at `/california/beach/<slug>` with today’s status, the last test, lab results against the limit, and the experimental forecast. The slug is the same one used on the public beach page.
- A phone-first home at `/` that lists the nearest beaches after the browser shares a location, and a search when it does not. The map on that screen loads only after “Show these on a map.” A station with coordinates outside a loose West Coast box, or with a published unknown-location flag, stays in that list and in search. It is left off every map and out of the near-me sort, and the build log names it. Monitored beaches just south of the border stay on the map. An `Unknown` water-quality call is not a location flag.
- No statewide total of beaches at elevated risk on the home page or in a beach summary. `SHOW_STATEWIDE_STATUS_COUNTS` in `lib/statewideCounts.ts` is off. The model is uncalibrated and runs high, so that total would mislead. Each beach still shows its own reading.
- A shareable `/beach/<slug>` page. Its summary states today’s status, the last lab test when a sample age was published, and the experimental outlook. Rain and the latest lab result appear only when those fields are in the file. A blank rain field is not described as a dry day. Locked or missing forecast days are not given a direction.
- Installable PWA basics: a web manifest and a service worker that always asks the network, so a saved page is not reused as today’s reading. English and Spanish on the public home and beach page. Beach names stay as published.
- “Last tested N days ago,” a calm limited-lab line, “Last updated,” and a banner when the forecast date is not today.
- “Past lab agreement,” not a confidence score.
- The statewide daily file `outputs/daily/current.csv` (a dated file next to it is history). It carries method, confidence, county posting, and Neptune Index columns. A closure, warning, or advisory is shown first, with its source when one was published, and our prediction stays visible under it. A warning still leads when the model estimate is under the limit. `open` means that source listed nothing active today. `unknown` is a plain note that no official posting data was published, with no badge, and it is not treated as safe. Low confidence is worded and styled as less certain than high confidence. A rain advisory appears only when the rules path flags recent rain. Empty index cells stay empty. A shown index is 0–100, and a higher number is cleaner. A county warning or closure labels that index Poor and does not invent one when the fields are empty. An old lab test or a fallback greys the band and adds a written note. Absent fields stay off the page.
